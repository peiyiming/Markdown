# Markdown 项目技术审计与重构计划

## 当前结论

仓库并不是没有代码，而是核心产品闭环没有实现。当前首页已经初始化 RecyclerView 和文件工具，但没有把扫描结果绑定为真正的可操作文件列表；因此“文件管理”和“Markdown 编辑”都没有形成完整体验。

## 主要技术债

1. Android Support Library 26.1.0，尚未迁移 AndroidX。
2. Kotlin Android Extensions 已废弃。
3. compileSdk/targetSdk 仍停留在 26。
4. HomeActivity 中存在未完成的 adapter 绑定逻辑。
5. Markdown 渲染资源存在，但缺少真正的编辑入口与编辑状态管理。
6. 文件、编辑器和预览职责尚未形成清晰的架构边界。
7. 缺少自动保存、异常恢复和测试体系。

## MVP 重构策略

采用渐进式改造，而不是一次性删除旧代码：

- 第一阶段：在现有技术栈中建立可运行的编辑器闭环。
- 第二阶段：实现文档新建、打开、保存和自动保存。
- 第三阶段：完成首页文件列表与编辑器导航。
- 第四阶段：迁移 AndroidX，并逐步升级至现代架构。

## 本分支已实现

- 新增 MarkdownEditorActivity。
- 新增原生文本编辑区。
- 新增编辑/预览模式切换。
- 复用仓库中的 marked.js 实现 Markdown HTML 渲染。
- 新增标题、粗体、斜体、链接和行内代码快捷输入。
- 新增独立 editor_preview.html，避免依赖旧预览页面的未知逻辑。

## 下一阶段优先级

P0：文档持久化
- 新建 .md
- 打开已有文件
- 保存
- 自动保存草稿

P1：文件工作区
- 最近文档
- 文件列表
- 重命名
- 删除

P2：体验升级
- Undo/Redo
- Markdown 语法高亮
- 图片插入
- 搜索

## 目标产品闭环

启动应用 → 新建或打开文档 → 编辑 Markdown → 快捷输入 → 实时预览 → 保存 → 再次打开。

在完成这个闭环之前，不建议过早投入复杂同步、账号系统或跨端能力。
